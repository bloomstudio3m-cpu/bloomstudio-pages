### 素材の出どころ（捏造していないことの確認）

0〜7秒の作業画面は、制作当時の画面録画がないため**制作ログから再現**しています。画面にも「制作ログから再現」と表示しています。中身はすべて実際の記録から取りました。

| 画面の要素 | 出どころ |
|---|---|
| エディタのコード | git `3933b0a`（初回コミット）の `index.html`（商品データの定義部分・実際の行番号）、`menu.html`、`README.md` を、ビルド時にgitから直接読み込んで表示 |
| 指示書 | MAIから渡された「Claude Code・Codex 共通制作指示書」の本文（1. プロジェクト概要／4. 必須機能から抜粋） |
| ターミナル | 実際に実行した操作と出力。初回テストは `Error: strict mode violation`（`locator('[data-inc="c1"]') resolved to 2 elements`）で止まり、セレクタを `#grid` に限定して再実行し、`0 failed / 32` になった。そのあと `.name { text-wrap: balance; }` を追加して初回コミット |
| 時計 | 作業開始時に記録した 06:06:38 UTC から、初回コミットの 06:12:05 UTC まで |
| プレビュー | 初回テストで実際に撮ったスクリーンショット（`screenshots/01_mobile_hero.png`、`03_mobile_cart_bar.png`） |

再現にあたって省いたこと・変えたこと：
- ターミナルの表示は汎用的な見た目にしています。Claude Codeの実際の画面をそのまま写したものではありません。
- 最初に受け取った入力は、zip内の共通プロンプトでした。正式な指示書は制作の途中で届き、それを反映しています。動画では指示書にまとめて表示しています。
- テストの出力は、32項目のうち代表的な6行だけを表示しています。

7秒以降は、実物のアプリ（`../index.html`）をローカルサーバーで動かし、iframeに読み込んで実際にタップして撮影しています。アプリ本体の差分はありません。

### 合格条件のセルフチェック

1. **冒頭2秒でAIによるWeb制作だとわかるか**：1フレーム目から、ターミナル（`$ claude`）とコードエディタが画面の大部分を占め、テロップ「AIにカフェの注文アプリを作らせた」が出ています。
2. **制作過程が映っているか**：指示書 → コードの生成 → ファイルの追加 → テストの失敗と修正 → 全項目合格 → コミットまで、時系列で映っています。
3. **コードから完成画面への変化がはっきりしているか**：プレビュー枠の中の小さなアプリが、作業画面を押しのけて0.55秒で全画面に広がります。そのあとすぐに「完成！」が大きく出ます。
4. **実際に操作できることが伝わるか**：タップ位置を丸で表示しています。ボタンが数量ステッパーに変わる様子、下部バーの点数と金額が変わる様子、確認から完了までが映っています。
5. **テンポにメリハリがあるか**：0〜7秒は情報が細かく速く流れ（コード34行/秒、テスト結果が0.08秒間隔）、7秒で一気に全画面へ広がります。その後は操作をはっきり見せるテンポに落としています。

### Dへの申し送り

1. **フォントが実機と違います。** 撮影環境（Linux）には日本語フォントがIPAゴシックしかありません。そのため動画の日本語は、iPhoneのヒラギノとは字形が違います。iPhone実機での見え方に揃えたい場合は、Macで `build-video.js` を実行し直せば、同じ台本のままヒラギノで書き出せます。
2. **リール版では、静的メニュー表が映るのは約1.4秒だけです。** 冒頭の2秒をテロップに使ったためです。比較動画で「静的メニュー → アプリ」の変化をはっきり見せたい場合は、`clips/01` と `clips/02`（clean版）を使うのがおすすめです。
3. **3.4〜4.6秒あたりで画面が一瞬白っぽくなります。** メニュー表が抜けてから「NOIR」が出るまでの間です。アプリ本来の動きなので、今回は変えていません。気になる場合は、編集で0.3秒ほど詰めることができます。
