# motion-v6｜主要3シーンのモーション設計

座標はCSSの px（405×720。書き出し時に×2.667で1080×1920）。時間は秒。イージングは自作の関数です。

- io3／io4：3次／4次のイーズインアウト
- o3：3次のイーズアウト
- oExpo：指数のイーズアウト

## シーン1：HOOK「AI BUILDS A WEBSITE」（0.0〜2.0）

目的：1秒目で「AIが何かを作っている」と伝わり、視線を奪うこと。

| レイヤー | Z | 動き |
|---|---|---|
| コード層A（奥） | −600 | 実際の行。毎秒30行で上に流れる。白35% |
| コード層B | −300 | 毎秒45行。白55% |
| コード層C（手前） | 0 | 毎秒60行。白85%。トークン（文字列・数値）は銀 |
| 文字 | +120 | 「AI BUILDS」0.30〜0.56、「A WEBSITE」0.56〜0.82。1文字ずつ `translateY(100%→0)`、o3、文字間隔0.045 |
| 銀の線 | +120 | 0.70〜0.95、文字の下を `scaleX 0→1` |

- **1.0〜2.0のカメラ**：Zを0→−900（io4）。文字は `clip-path inset` で上へ抜ける（1.0〜1.2）。コード行には行ごとに異なるZのずれ（最大−420）を与え、奥行き方向にばらけさせる。
- **判読性**：文字は高さ約1/6（300px以上）。コードは読ませないが、本物のコードであることは近づけばわかる。

## シーン2：3D LAYERS → TEST（4.0〜7.0）

目的：エディタ・テスト・プレビューが同時に動いている「制作中の空間」を見せること。

| パネル | 位置 / Z | 中身 |
|---|---|---|
| エディタ | x −40 / Z −240 | 3933b0aのコードが書き出されていく（毎秒34行） |
| ターミナル | x 0 / Z 0 | 実際のコマンドと出力 |
| プレビュー | x +60 / Z +240 | 初回テストで撮ったスクリーンショット |

- **4.0〜5.0のカメラの回り込み**：ワールドを rotateY 0→28°、translateX 0→−30（io3）。手前のパネルほど大きく横に動くので、パララックスで奥行きが読める。
- **5.0〜6.0のTEST**：ターミナルがZ 0→+160に出てくる（o3、0.3秒）。エラー行の帯を rotateX 0→180° で裏返し、裏面は `0 failed / 32`（io3、0.35秒）。数字のカウンターは 0→32 を0.4秒で回し、1桁ずつマスクで上がる。キーワード「TEST」はシーン1と同じ文字演出。
- **6.0〜7.0のカメラ**：プレビューへ向かってZを前進し、rotateY 28→0°（io4）。7.0ちょうどでプレビューが画面の中心で正対し、変形シーンの開始位置につなぐ。
- **時計**：06:06:38→06:12:05 UTC を4.0〜6.8で線形に刻む。等幅フォントで、文字幅が変わらないようにする。

## シーン3：CODE → UI（7.0〜9.0）※試作済み `proto-code-to-ui-2s.mp4`

目的：コードの値が、そのまま実物のUIの部品になることを、目で追えるように見せること。

| 区間（試作内の時刻 → 本編の秒数） | 動き |
|---|---|
| 0.00〜0.20（7.00〜7.20） | エディタ内の6つの値（`latte`、`モノクロ・ラテ`、`Monochrome Latte`、説明文、`580`、`class="add"`）の下に、銀の線を `scaleX` で順番に引く（間隔0.025秒） |
| 0.10〜1.00 | エディタが奥へ退く：translateZ 0→−760、rotateY −12→−46°、rotateX 4→10°（io3）。**各行が別々のZ（−40〜−460）とX（±44）にばらけて分解する** |
| 0.12〜0.87 | 6つの値が飛ぶ。開始は0.05秒間隔、飛行時間は絵が0.36秒・ほかは0.48秒（io3）。手前に浮く弧（−34〜−64px）と、途中で最大+16%の拡大。**着地点は実物のアプリの要素位置をその場で計測したもの** |
| 0.42×飛行時間〜0.78×飛行時間 | 書体のモーフ：銀のスキャンラインが左から右へ走り、等幅の文字をclip-pathでサンセリフに書き換える（クロスフェードは使わない） |
| 0.16〜0.50 | カードの4辺の延長上に精密ガイド線（銀55%）が画面端まで伸び、0.75〜0.98で消える |
| 0.30〜0.62 | カードの縁を銀の線で描く（上と左は左上の角から、下と右は右下の角から伸ばす） |
| 0.42〜0.64 | 絵：`latte` の文字が銀の枠に広がって絵の領域になり、そこへ実際のSVGが下から上へマスクで塗り上がる |
| 0.30〜0.55 | 本文の領域が紙の色で上から下へ塗られ、文字の着地点になる |
| **1.00〜1.38（8.00〜8.38）** | **最大の見せ場**：実物のアプリ（iframe）をカードの矩形から `clip-path inset` で全画面へ開く（io4）。組み上げたカードと実物のカードはピクセル位置が一致しているので、境目なしで本物に入れ替わる |
| 0.95〜1.45 | アプリのレイヤーのカメラ：scale 0.86→1.0（oExpo）、translateY 10→0 |
| 1.26〜1.85 | READY：黒い帯が左から `scaleX` で伸び（io4、0.2秒）、銀の文字「READY」が1文字ずつ下から上がる。右下に `ALL TESTS PASSED · 32/32`（実際の結果） |

## 技術選定と記録

| 用途 | 使ったもの | 理由 |
|---|---|---|
| シーンの描画 | HTML／CSS（3D変形、clip-pathマスク、グラデーション文字）＋自作のタイムライン（`__render(t)`） | 秒数から各フレームを決めて描くので、毎回同じ結果になる。実物のアプリと同じブラウザで描くため、境目なしで入れ替えられる |
| 書き出し | Playwright（同梱のChromium）＋ CDP `Page.captureScreenshot`（scale 2.667で再ラスタライズ） | 1080×1920で文字がにじまない |
| 動画化 | FFmpeg（libx264、CRF 14、yuv420p、30fps） | SNSで再生互換性の高い形式 |
| 使っていないもの | GSAP、Three.js、Remotion、Canva | 実際にやりたい動き（3D平面・マスク・FLIP）はCSSで足り、依存を増やさずに済むため。本編で粒子や本格的な3Dが必要になったら、Three.jsを追加して検討する |

## 試作の自己評価（D審査の参考）

- **よくできたところ**：分解したコード行の奥行き、値が着地する精度、マスクで実物のアプリに入れ替わる瞬間。
- **弱いところ**：0.40〜0.50秒あたりで飛んでいる値同士が重なり、一瞬ごちゃつく。本編では開始の間隔を0.05秒→0.065秒にして、弧の高さを値ごとにもっと変える予定。
- **フォント**：撮影環境の日本語はIPAゴシックで、iPhoneのヒラギノとは字形が違う（Macで書き出せば揃う）。
